# ニュートン法と代数シグモイドニュートン法のパフォーマンス比較レポート (Failsafe 無効)

## 1. はじめに

本レポートは、`ellphi`パッケージに実装されている接点探索ソルバーにおける、標準的な `newton` メソッドと `algsig+newton` (代数シグモイド変換を伴うニュートン法) メソッドのパフォーマンスを比較したものである。特に、**フェイルセーフ機構を無効化**した状態で、両メソッドの安定性、収束性能、および実行速度を評価することを目的とする。`algsig+newton` は、最適化変数を有界区間 (0,1) 内に維持しつつ、非有界空間でニュートン法を適用することで、数値的安定性の向上を目指す手法である。

## 2. 実験設定

### 2.1. 使用スクリプト

`scripts/hybrid_tuning.py` スクリプトを用いてベンチマークを実行した。

### 2.2. パラメータ

以下のパラメータで実験を実施した。

*   **次元 (`--dims`)**: 5, 10, 20
*   **サンプル数 (`--samples-per-dim`)**: 各次元で100
*   **バックエンド (`--backends`)**: `python`, `cpp`
*   **メソッド (`--methods`)**: `newton`, `algsig+newton`
*   **フェイルセーフ (`--failsafe`)**: `false` (無効化)

### 2.3. 評価指標

各バックエンドおよびメソッドの組み合わせについて、以下の指標を収集・評価した。

*   **失敗数 (Failures)**: 根の探索に失敗したサンプル数。
*   **実行時間 (Time Mean/Median/P99)**: 平均、中央値、99パーセンタイル実行時間 (ミリ秒)。
*   **誤差 (Error Mean/Median/P99)**: 最終的な残差の平均、中央値、99パーセンタイル。

## 4. 詳細な分析

### 4.1. C++ バックエンドの挙動

*   **極めて高い安定性**: C++ バックエンドは、`newton_nofailsafe` および `algsig+newton_nofailsafe` の両方で、**全てのテストケースにおいて失敗数0**という優れた結果を示した。これは C++ 実装の堅牢性、特に劣悪な条件の行列に対するカスタムな線形代数処理が非常に効果的であることを裏付けている。
*   **誤差の挙動**:
    *   `algsig+newton_nofailsafe`: 非常に低い誤差 (Error Mean が $10^{-12}$ 程度) で安定して収束した。
    *   `newton_nofailsafe`: 平均誤差 (Error Mean) および 99パーセンタイル誤差 (Error P99) が高次元で顕著に高くなるケースが見られた。これは、C++ の `newton` 実装が `failsafe` が無効な場合、厳密な収束条件を満たさなくても結果を返し、それを失敗とはカウントしない挙動を持つ可能性を示唆する。しかし、`algsig+newton` は常に非常に高い精度で収束している。
*   **実行速度**: C++ バックエンドは、両メソッドともに非常に高速であり、平均実行時間は 0.1 ミリ秒未満に収まっている。

### 4.2. Python バックエンドの挙動

*   **`algsig+newton_nofailsafe` の失敗**: `algsig+newton_nofailsafe` は全体で23件の失敗を記録し、特に高次元 (dim 20 で10件) で失敗数が増加する傾向が見られた。これは `newton_nofailsafe` (全体で7件の失敗) よりも多い結果であり、一見すると `algsig` 変換が安定性向上に寄与していないように見えるかもしれない。
    *   **考察**: この意外な結果は、`algsig_newton` の内部実装における堅牢性チェックの厳しさ (例: `isfinite` チェック、バックトラッキングラインサーチの失敗判定) に起因すると考えられる。`algsig_newton` は変換空間でのニュートン法であるため、より多くの条件で「非収束」を判断し、`failsafe` が無効なシナリオではそれが直接失敗として計上される。対照的に、純粋な `newton` は、`algsig_newton` が非収束と判断するような状況でも、何らかの値を返すことがあるのかもしれない。
*   **`newton_nofailsafe` の安定性**: Python の `newton_nofailsafe` は7件の失敗に留まっており、以前に導入された `lstsq` フォールバック (劣悪な条件の線形システムに対する頑健な近似解法) の恩恵を強く受けていることが示唆される。この `lstsq` フォールバックがなければ、`newton_nofailsafe` の失敗数はもっと多かったと推測される。
*   **実行速度**: Python バックエンドは、C++ バックエンドと比較して顕著に遅く、平均実行時間は約 0.7〜1.0 ミリ秒であった。`algsig+newton` は変換処理のオーバーヘッドのため、わずかに `newton` よりも遅い傾向があるが、その差は小さい。
*   **誤差の挙動**: 成功した場合の誤差は、両メソッドともに非常に低い値を示しており、収束に成功した場合は高精度な解が得られていることを示している。

### 4.3. 次元増加の影響

*   Python バックエンドでは、次元が増加するにつれて `algsig+newton_nofailsafe` の失敗数が増加する傾向が見られた (dim 5: 6件 -> dim 20: 10件)。これは、高次元における非有界空間での探索が、依然として課題を抱えている可能性を示唆する。
*   C++ バックエンドは次元による影響を受けず、すべての次元で安定していた。

## 5. 考察と結論

### 5.1. C++ バックエンドの優位性

C++ バックエンドは、フェイルセーフが無効な状況においても、`newton` と `algsig+newton` の両メソッドで極めて高い安定性 (0失敗) と優れたパフォーマンス (高速な実行時間) を示した。特に `algsig+newton` は常に高精度な解を返す点で優れている。

### 5.2. Python バックエンドの課題と `algsig` の役割

Python バックエンドでは、`failsafe` が無効な場合、`algsig+newton` は純粋な `newton` よりも失敗率が高いという結果になった。これは、`algsig_newton` の内部的な堅牢性チェック (特にバックトラッキングラインサーチや `isfinite` 判定) が厳格であるため、非収束のケースをより積極的に失敗として計上していることに起因すると考えられる。

この結果は、`algsig` 変換の真の価値が、**`failsafe` 機構と組み合わせることで、より困難な問題に対してもニュートン法の堅牢な解探索を可能にする点**にあることを示唆している。つまり、`algsig` 変換は、ニュートン法の探索空間を安定化させることで、`failsafe` が最終的に介入して成功する可能性を高める役割を果たす。純粋な `newton` 単体 (Python) は、`lstsq` フォールバックの恩恵により以前よりも安定しているものの、`algsig+newton` の持つ可能性を最大限に引き出すためには、`failsafe` との併用が重要である。

### 5.3. 今後の方向性

Python バックエンドの `algsig+newton` は、C++ バックエンドに匹敵する安定性を達成するためには、`failsafe` との組み合わせが不可欠であることが再確認された。また、Python の数値計算の速度は C++ に比べて遅いため、パフォーマンスがボトルネックとなる場合は引き続き C++ バックエンドの利用が推奨される。
